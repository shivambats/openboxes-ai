## Fixes found by connecting to the real app

1. Use `bootRepackage`: Docker executes the WAR with `java -jar`.
2. The existing Liquibase 1.9 schema rejects `modifyDataType`. Use the compatible
   MySQL/MariaDB column alteration for full Markdown comments.
3. A sandbox Organization must have its required default organization PartyType.
4. Serialize seeding on the existing sidecar Role row. Do not lock a newly
   constructed Organization before Hibernate has inserted it.
5. Persist/flush the initial SHIPPED Event before saving the Shipment. Its
   `beforeInsert` callback sets `currentEvent`, which has a foreign key to Event.
6. Native `currentStatus` has no CANCELLED or DELIVERED values. The sidecar's
   status mapping examines native events and blocks those terminal shipments in
   both polling and the server-side write guard. CUSTOM audit events leave the
   native SHIPPED status unchanged (API representation: IN_TRANSIT).
7. Preview reports pending uncertain writes even when a shipment is no longer
   overdue. The exact original payload remains in SQLite for safe replay.

## Resume after Docker storage recovery

Restarting Docker Desktop interrupts all containers and requires the operator's
approval. Once storage is writable, deploy the already-built corrected WAR:

```sh
docker compose -f docker/docker-compose.yml -f docker/docker-compose-sidecar.yml up -d --build app
```

Wait for `/openboxes/auth/login` to respond successfully. From `sidecar/`, load
the ignored local `.env` explicitly (`set -a; source .env; set +a`). It contains
the bot's intended password, not proof that its account has been created.

1. Run `.venv/bin/python seed.py` with a separate superuser login, supplied by
   prompt or `OPENBOXES_ADMIN_USERNAME`/`OPENBOXES_ADMIN_PASSWORD`.
2. Put the returned destination ID into `OPENBOXES_LOCATION_ID` in `.env` and
   reload it. Never give the runtime bot the admin credentials.
3. Ensure the mock portal is serving on localhost:8080.
4. Run `.venv/bin/python verify_live.py`. This must verify both carrier paths and
   denied unrelated routes without changing WMS records.
5. Run `.venv/bin/python verify_live.py --apply`. This must save the future ETA,
   one report and exactly three success events for each fixture. It also tests
   exact-payload replay and no-op repeat execution by reading saved histories.
6. Run `.venv/bin/python main.py --apply`: both updated fixtures should be absent
   from the overdue set and produce no duplicate activity.
7. Repeat seeding once to check that it preserves credentials, ETAs and history.
8. Disable `SIDECAR_SANDBOX_ENABLED` on the application after setup.

The fixed carrier ETA is **2026-09-24 10:00 UTC**. After that time it is stale and
must produce human review, not a fabricated future ETA. Change/review fixtures
explicitly before testing a later date; do not silently override the clock in a
live sweep.

The verifier and entrypoint use the same process lock and durable journal.
If a write response is lost, recover via `main.py --apply`; do not delete the
journal to make a test pass. HTTP 409 requires inspecting current history and the
pending operation rather than generating a new key blindly.
